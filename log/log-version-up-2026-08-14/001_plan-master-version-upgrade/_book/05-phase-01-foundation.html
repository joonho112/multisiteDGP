6  Phase 1 — 작업 기반 복구

6.1 목표

버전 관리와 실행 환경을 복구해서, 이후 모든 작업이 diff 기반으로 진행되고 되돌릴 수 있게 만든다. Phase 1 은 package 의 동작을 전혀 바꾸지 않는다 — 오직 그것을 안전하게 만질 수 있는 기반을 만든다.

이 Phase 가 첫 번째인 이유는 단순하다. Ch.1 A-1 이 확인했듯 로컬 작업본은 git repository 가 아니고, 원격 main 과 3 개월의 미확인 격차가 있다. 이 상태에서 코드를 고치면 무엇이 원래 상태였는지 영원히 알 수 없게 된다.

Step 수 5 (1.1 – 1.5)
누적 시간 ~85 분
선행 Phase 없음 (계획 승인 G-A)
종료 로그 002_phase01-foundation-recovery.qmd

6.2 Step 1.1 — 로컬 작업본과 원격 main 의 차이 확정

항목 값
모드 단일
소요 ~20 분
의존 없음 (계획 승인 후 첫 Step)

목표. 원격 joonho112/multisiteDGP 의 main 을 스크래치 영역에 클론하고, 로컬 작업본과 파일 단위로 비교해서 3 개월 격차의 정체를 확정한다. 어느 쪽이 최신인지, 로컬에만 있는 변경이 무엇인지, 원격에만 있는 변경이 무엇인지를 목록으로 만든다.

작업.

  1. 스크래치에 원격 클론 (log/log-version-up-2026-08-14/artifacts/remote-main-clone/ 이 아니라 세션 스크래치 — 저장소를 오염시키지 않는다)
  2. diff -rq 로 파일 단위 비교. .Rbuildignore 대상, docs/, _files/, 빌드 산출물은 제외
  3. 차이 나는 파일을 3 분류: 로컬만 있음 / 원격만 있음 / 양쪽 다 있으나 내용 다름
  4. 세 번째 분류의 각 파일에 대해 어느 쪽이 최신인지 판정 (mtime + 내용 검토)
  5. 원격 main 의 최근 커밋 20 개 로그 확보 — 로컬 상태가 어느 커밋에 대응하는지 추정

산출물.

  • log/log-version-up-2026-08-14/evidence/phase01/local-vs-remote-diff.md — 3 분류 표 + 판정 근거
  • log/log-version-up-2026-08-14/evidence/phase01/remote-main-log.txt — 원격 커밋 로그
  • 판정 결론 한 문장: “로컬이 원격의 superset / subset / 분기” 중 하나

완료 조건.

  • 차이 나는 모든 파일이 3 분류 중 하나에 배정되어 있다
  • “양쪽 다 있으나 내용 다름” 분류의 각 파일에 최신 판정과 근거가 있다
  • 로컬이 원격보다 앞서는지 뒤처지는지가 한 문장으로 결론 나 있다

이 Step 은 읽기 전용이다. 어떤 파일도 복사하거나 덮어쓰지 않는다. Step 1.2 가 판정에 따라 조치한다.

6.3 Step 1.2 — git 복구 및 브랜치 전략 확정

항목 값
모드 단일
소요 ~20 분
의존 1.1

목표. 로컬 작업본을 git 관리 하에 두고 원격과 연결한다. Step 1.1 의 판정에 따라 복구 경로가 갈린다.

복구 경로 (1.1 판정에 따라 택일).

1.1 판정 경로
로컬 == 원격 원격을 클론한 뒤 로컬 고유 파일을 얹는다. 가장 단순
로컬이 원격의 superset (로컬이 앞섬) 원격 클론 → 로컬 상태를 작업 트리에 반영 → chore: restore local working state 단일 커밋
로컬이 원격보다 뒤처짐 PI 확인 필요. 로컬에서만 한 작업이 있는지 물어보고 진행
분기 (양쪽 고유 변경 존재) PI 확인 필요. 병합 방침 결정 후 진행

작업.

  1. 복구 경로 실행 — .git 이 로컬 작업 디렉터리에 존재하고 origin 이 연결된 상태를 만든다
  2. git status 가 깨끗한지 확인. 안 깨끗하면 .gitignore / .Rbuildignore 를 점검 (Step 1.4 와 조율)
  3. 브랜치 전략 확정 및 문서화 — 기본안은 Ch.3 의 upgrade/phase-NN-<slug>
  4. Phase 1 작업 브랜치 생성: upgrade/phase-01-foundation
  5. 복구 시점 상태를 태그: pre-upgrade-baseline

산출물.

  • git 관리 하의 작업 디렉터리 (.git 존재, origin 연결, 작업 트리 clean)
  • pre-upgrade-baseline 태그 (로컬 + 원격 push)
  • upgrade/phase-01-foundation 브랜치
  • log/log-version-up-2026-08-14/decisions/branch-strategy.md

완료 조건.

  • git rev-parse --is-inside-work-tree → true
  • git remote -v 가 joonho112/multisiteDGP 를 가리킨다
  • git status --porcelain 출력이 비어 있다
  • pre-upgrade-baseline 태그가 원격에 있다
Important되돌릴 수 없는 Step

이 Step 전에 작업 디렉터리 전체를 압축 백업한다. 경로: log/log-version-up-2026-08-14/artifacts/pre-git-recovery-backup.tar.gz (.Rbuildignore 에 추가). git 복구 중 사고가 나면 여기서 복구한다.

  1. 제거 대상 처리 — 각각 삭제 전에 내용을 확인하고, 원격에 없는 고유 정보가 있으면 보존

    • multisiteDGP_0.0.0.9000.tar.gz, multisiteDGP_0.1.0.tar.gz — 과거 빌드. artifacts/ 로 이동 후 작업 루트에서 제거
    • Library/, Outputs/ — 빈 디렉터리. 삭제
    • .DS_Store — 삭제 + .gitignore 등재
    • blueprint-multisiteDGP-book-v1.0-20260507.zip (41 MB) — 원본 book 폴더가 존재하므로 중복. artifacts/ 이동 또는 삭제 (PI 확인)
  2. .gitignore 작성 또는 갱신 — 위 패턴 + _book/, _files/, *.Rcheck/, .quarto/
  3. .Rbuildignore 점검 — 새 log 폴더 ^log$ 가 이미 등재되어 있는지 확인 (등재되어 있음)
  4. 정리 후 R CMD build 로 tarball 을 만들어 크기와 포함 파일 확인
