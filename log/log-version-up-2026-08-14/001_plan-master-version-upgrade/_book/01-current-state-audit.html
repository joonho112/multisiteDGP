2  현재 상태 감사

이 장은 2026-08-14 에 실측한 package 상태다. 추측이나 기억이 아니라 실행 결과와 원격 CI 로그에서 나온 것만 적는다. 원자료는 부록 B 에 있다.

Phase 2 는 이 장을 출발점으로 삼되 그대로 믿지 않는다. 이 감사는 planning agent 가 한 세션에 훑은 결과이므로, Phase 2 가 각 영역을 체계적으로 재감사해 부록 A 결함 원장 을 확정한다.

2.2 A. 공학 기반 — 심각

2.2.1 A-1. 로컬 작업본이 git repository 가 아니다

$ git rev-parse --is-inside-work-tree
fatal: not a git repository (or any of the parent directories): .git

상위 디렉터리에도 없다. 그런데 원격은 살아 있다.

$ gh repo view joonho112/multisiteDGP --json name,visibility,pushedAt
{"name":"multisiteDGP","pushedAt":"2026-05-10T04:41:33Z","visibility":"PUBLIC"}

함의. ① 2026-05-10 이후 로컬에서 무엇이 바뀌었는지 알 방법이 없다. ② 로컬과 원격 중 어느 쪽이 최신인지 모른다. ③ 이후 모든 수정 작업이 diff · 브랜치 · PR 없이 진행되면 되돌릴 수 없다. ④ .github/workflows/ 6 개, .pre-commit-config.yaml, CONTRIBUTING.md 가 전부 무의미하다.

이것이 Phase 1 이 존재하는 이유이며, 다른 어떤 작업보다 먼저다.

2.2.2 A-2. CI 가 2026-05-10 이후 계속 red

gh run list --repo joonho112/multisiteDGP --limit 15 결과 요약:

릴리스 태그 0 건, 이슈 0 건.

함의. 공개 pkgdown 사이트만 성공해서 밖에서 보기에는 건강해 보인다. 실제로는 품질 게이트 4 개 중 4 개가 3 개월간 꺼져 있었다. 2026-05-10 push 세 workflow 의 로그는 GitHub 보존 기간(90 일)이 지나 만료됐으므로, Phase 2 는 재현으로 원인을 규명해야 한다 (로그 조회가 아니라 로컬 Linux 컨테이너 또는 CI 재실행).

2.2.3 A-3. 저장소 위생

빌드 산출물과 빈 디렉터리가 작업 디렉터리에 방치되어 있다.

항목 상태
..Rcheck/ 존재 — 다른 경로(IES Multisite Trial Project, 00_ 접두사 없음)에서 실행된 잔재. DESCRIPTION Author/Maintainer 누락 ERROR 기록

multisiteDGP_0.0.0.9000.tar.gz, multisiteDGP_0.1.0.tar.gz 존재 (각 ~420 KB)
blueprint-multisiteDGP-book-v1.0-20260507.zip 존재 (41 MB)

..Rcheck/00check.log 의 Required fields missing or empty: 'Author' 'Maintainer' 는 source directory 를 직접 check 해서 나온 것이며 Authors@R 은 정상이다. 실제 결함이 아니라 오래된 잔재가 만든 가짜 신호이므로, 이런 잔재는 제거해야 이후 진단이 오염되지 않는다.

2.3 B. 재현성 계약 — 심각

2.3.1 B-1. Linux CI 에서 canonical_hash 만 불일치

extended-tests (2026-07-13) 실패 로그 발췌:

── 5. Failure ('test-snapshot-print.R:87:5'): summary.multisitedgp_data snapshot
       feasibility_index:          14.431  (target N/A)  WARN  [no target]
    Overall: 3 PASS, 3 WARN, 2 FAIL.
-   Provenance: ... seed=12345 | canonical_hash=128c43fb9cfc4416 | design_hash=db50cfd4e1659537 | ...
+   Provenance: ... seed=12345 | canonical_hash=7b960a5122df9c88 | design_hash=db50cfd4e1659537 | ...

세 가지를 동시에 읽어야 한다.

  1. 출력 수치는 전부 동일하다 — feasibility_index 14.431, PASS/WARN/FAIL 카운트, 진단 라인 모두 일치.
  2. design_hash 는 동일하다 (db50cfd4e1659537) — design 객체 직렬화는 플랫폼 중립이다.
  3. canonical_hash 만 다르다 — 생성된 데이터 가 표시 정밀도까지는 같지만 비트 수준에서 다르다.

즉 문제는 “Linux 에서 다른 값이 나온다” 가 아니라 “부동소수점 최하위 비트가 다른데 해시 계약이 그것을 흡수하지 못한다” 이다. R 의 RNG 자체는 플랫폼 간 동일하므로, 드리프트 원인은 libm 차이(macOS Apple libm vs glibc), nleqslv solver 반복, sn package 내부 계산, 또는 long-double 누산 중 하나로 좁혀진다. Phase 4 Step 4.1 이 이를 특정한다.

실패한 snapshot 은 최소 10 건 (testthat 이 10 건에서 절단) — test-snapshot-print.R 7 건, test-generated-print-examples-step8-6.R 2 건 이상.

2.3.2 B-2. 정책 문서와 체크인된 아티팩트가 모순

tools/cross-os-reproducibility-policy.md 는 이렇게 규정한다.

Linux is the strict cross-run hash baseline. … Authoritative golden and print-example regeneration is Linux-only.

그리고 같은 문서가 스스로 모순을 자백한다.

Current v0.1 golden fixture note: the checked-in Step 8.1 manifest records local macOS/aarch64 provenance (generated_platform = aarch64-apple-darwin20) for the nine bootstrap fixture files.

정책은 Linux 를 authoritative 로 규정하는데 실제 체크인된 것은 macOS 산출물이다. 이것이 B-1 실패의 직접 원인이다. NEWS.md 의 “Known limitations” 에도 “The Linux x86_64 baseline is pending the first continuous-integration run” 으로 적혀 있으나, 그 CI 실행이 10 주 연속 실패하면서 3 개월간 방치됐다.

2.3.3 B-3. 로컬에서는 이 문제가 보이지 않는다

skip_if_not_linux_strict_hash() 가 macOS/Windows 에서 T1a 를 항상 skip 시킨다. slow + property 게이트를 전부 켜고 돌려도 로컬에서 skip 되는 유일한 테스트가 T1a 다. 즉 PI 의 개발 머신에서는 이 계약이 검증되는 일이 영원히 없다.

2.4 C. 테스트 스위트 무결성 — 심각

2.4.1 C-1. 기본 실행이 30 개를 skip 한다

$ Rscript -e 'devtools::load_all("."); testthat::test_local(".")'
══ Skipped ═══════════════════════════════════════════════════
[30 건]
══ DONE ══════════════════════════════════════════════════════
💅 Your tests are beautiful 💅

skip 사유별 분포:

사유 건수 숨겨진 내용
MULTISITEDGP_RUN_SLOW 22 표준화 계약 T13(ALD) · T14(Mixture) · T15(Student-t) · T16(SkewN) · T17(PMSlab), 분포 검정 T1b · T4 · T9, JEBS I-grid T11, truncation T10

tests/testthat/helper-skip-policy.R 에 skip_if_not_validation(), skip_if_api_missing() 도 정의되어 있다.

함의. 이 package 의 과학적 주장 — “여덟 개 분포 shape 가 단위분산 규약을 공유하므로 heterogeneity ratio 목표가 shape 를 가로질러 같은 의미를 갖는다” — 를 검증하는 테스트가 전부 기본 실행에서 빠져 있다. 개발자가 매일 보는 green 은 배관(plumbing) 만 검증한 green 이다.

2.4.2 C-2. 게이트를 켜면 로컬에서는 통과한다

$ MULTISITEDGP_RUN_SLOW=true MULTISITEDGP_RUN_PROPERTY=true Rscript -e '...test_local(".")'
══ Skipped ═══════════════════════════════════════════════════
1. T1a Engine A1 Mixture matches JEBS appendix golden fixtures
   - Reason: Strict canonical_hash equality is Linux x86_64/amd64 baseline only.
══ DONE ══════════════════════════════════════════════════════
💅 Your tests are beautiful 💅

좋은 소식이다. 통계 커널 자체는 건강하다. 문제는 코드가 아니라 게이트 정책 이다. 켜기만 하면 되는데 아무도 켜지 않는 구조로 되어 있다.

이 사실이 v0.2.0 의 성격을 결정한다 — 커널 재작성이 아니라 계약과 게이트의 재설계.

2.4.3 C-3. Suggests 3 개가 로컬에 없다

package 역할 없을 때 결과
copula align_copula_corr() Gaussian copula 경로 copula 의존 테스트 부분 검증 또는 skip
multisitepower as_multisitepower() adapter adapter 테스트 skip (CRAN 미배포 — 문서화된 예외)
hedgehog property-based 테스트 P01–P12 의 생성기 기반 검증 축소

hedgehog 부재는 특히 문제다. C-2 에서 property 테스트가 “통과” 했지만, hedgehog 없이 어떤 경로로 통과했는지 Phase 2 Step 2.2 가 확인해야 한다.

2.5 D. 광고와 구현의 갭 — 중간

DESCRIPTION 은 이렇게 광고한다.

generates latent site effects under a catalog of eight distribution shapes (Gaussian, Student-t, skew-normal, asymmetric Laplace, two-component mixture, point-mass slab, user callback, and a Dirichlet-process-mixture bridge)

실제 코드:

위치 코드 실제 동작
R/layer1-gen_effects_dpm.R:127 "`true_dist = \"DPM\"` is not implemented in multisiteDGP v1." 호출 시 hard abort (E22)
R/layer1-gen_effects.R:191 "`upstream` is reserved and is not implemented yet." 인자 존재, 미구현

“stub-not-silent” 정책 (blueprint ch.05 §8) 자체는 옳다 — 조용히 틀린 값을 주는 것보다 낫다. 문제는 DESCRIPTION 이 그것을 여덟 번째 shape 로 세고 있다는 것이다. NEWS.md 도 8 개 분포를 나열하며 gen_effects_dpm() 을 포함한다.

이건 코드 버그가 아니라 정직성 결함이다. 처리 방향은 두 갈래이며 (구현 vs 광고 축소) Phase 3 에서 PI 가 정한다.

2.8 한 줄 요약

Important진단 요약

multisiteDGP 의 통계 커널과 문서는 건강하다. 무너진 것은 그것을 지탱하는 공학 기반 — 버전 관리 부재, 3 개월 red CI, 30 개가 숨겨진 테스트 게이트, 정책과 어긋난 재현성 아티팩트, 광고와 어긋난 API 표면. v0.2.0 은 새 기능을 더하는 릴리스가 아니라 기존 표면을 믿을 수 있게 만드는 릴리스다.
