7  Phase 2 — 결함 인벤토리 감사

7.1 목표

추측이 아니라 증거로 결함 원장을 구축한다. Ch.1 의 감사는 planning agent 가 한 세션에 훑은 결과다. Phase 2 는 각 영역을 체계적으로 재감사해서 ① 재현 절차가 붙은 결함 목록과 ② P0/P1/P2 트리아지를 확정한다.

Phase 2 는 아무것도 고치지 않는다. 감사 중 명백한 버그를 발견해도 원장에 등재만 하고 지나간다. 수정은 Phase 4 · 5 · 7 이 원장을 소비하며 수행한다. 이 분리가 없으면 감사가 임기응변 수정으로 흩어지고 원장이 완성되지 않는다.

Step 수 9 (2.1 – 2.9)
누적 시간 ~175 분
선행 Phase Phase 1
종료 로그 003_phase02-defect-audit.qmd
Note감사 마비 방지

Phase 2 의 실패 모드는 결함을 계속 발견하며 끝나지 않는 것이다. Step 2.9 에서 원장을 닫는다. 이후 발견분은 v0.3 백로그로 간다. 각 감사 Step 은 배정된 시간 안에 끝내고, 더 파야 할 것이 보이면 “추가 조사 필요” 행을 원장에 남기되 그 자리에서 파지 않는다.

작업.

7.6 Step 2.5 — 통계 커널 감사 ①: Layer 1

항목 값
모드 단일
소요 ~20 분
의존 2.2

목표. 여덟 개 분포 shape 의 표준화 계약 이 실제로 지켜지는지, 그리고 미검증 경계 가 어디인지 확정한다.

작업.

  1. 표준화 계약 재확인 — 각 shape 에 대해 큰 표본에서 mean(z_j) ≈ 0, var(z_j) ≈ 1 을 직접 측정. T13–T17 이 이미 검증하지만, 여기서는 테스트가 쓰는 것보다 넓은 파라미터 격자에서 확인
  2. 경계 파라미터 탐색 — 각 shape 의 파라미터 공간 가장자리에서 무슨 일이 일어나는가
    • Student-t: nu 가 2 에 가까울 때 (분산 발산 직전)
    • SkewN: alpha 극단값
    • ALD: 극단 비대칭
    • Mixture: pi 가 0 또는 1 에 가까울 때, ups 극단
    • PMSlab: pi0 가 0 또는 1
  3. fail-fast 검증 — 위 경계에서 abort 해야 하는데 조용히 이상한 값을 주는 경우가 있는가? 반대로 유효한 파라미터인데 불필요하게 abort 하는가?
  4. gen_effects_user() callback 계약 — g_returns = "standardized" / "raw" 두 경로, RNG 격리, 오류 전파
  5. covariate 경로 — formula + beta 가 있을 때 residual/marginal 분해가 문서와 일치하는지

산출물.

  • evidence/phase02/layer1-audit.md — shape 별 표준화 검증 + 경계 동작표
  • evidence/phase02/layer1-parameter-grid.csv — 실행한 파라미터 격자와 결과
  • 원장 행: Layer 1 관련 결함

완료 조건.

  • 8 shape 전부에 대해 표준화 계약 검증 결과가 있다
  • 각 shape 의 경계 파라미터 동작이 기록되어 있다 (정상 / abort / 조용한 이상값)

작업.

  1. Step 2.1–2.8 의 원장 행을 defect-ledger.csv 로 통합. 스키마는 부록 A
  2. 중복 제거 — 여러 감사 Step 이 같은 근본 원인을 다른 증상으로 잡은 경우 통합

  4. 트리아지 — 각 행에 P0/P1/P2 배정
    • P0 — v0.2.0 릴리스를 막는다. 성공 기준 G1–G7 중 하나를 직접 위협하는 것
    • P1 — 고쳐야 하지만 비용이 크면 v0.3 으로. 사용자에게 보이는 결함이되 릴리스를 막지는 않음
    • P2 — 있으면 좋은 것. v0.3 백로그 기본
  5. Phase 배정 — 각 P0/P1 행이 Phase 4 / 5 / 7 중 어디서 처리될지 지정
  6. 재현 절차 검증 — P0 각 행의 재현 절차를 실제로 한 번씩 실행해서 재현되는지 확인. 재현 안 되면 P0 에서 강등
  7. 원장 잠금 — 이후 발견분은 status deferred-v0.3 이 기본임을 원장 헤더에 명시
