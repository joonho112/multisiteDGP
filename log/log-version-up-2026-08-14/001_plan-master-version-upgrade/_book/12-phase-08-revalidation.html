13  Phase 8 — 통계 검증 재실행

13.1 목표

Phase 4 · 7 의 변경 이후에도 package 의 통계적 주장이 성립함을 증명한다. 2026-05 에 수행된 validation experiment V0–V12 를 재실행하고, 이번에는 Linux 를 포함한다.

이 Phase 가 필요한 이유는 두 가지다. ① Phase 7 이 수치 동작을 바꿨을 수 있다. ② 원래 validation 이 macOS 로컬에서만 실행됐고 cross-OS 매트릭스는 “external to the local validation jobs” 로 미뤄져 있었다 (cross-os-reproducibility-policy.md). Phase 6 이 CI 를 복구했으므로 이제 그 미룬 일을 할 수 있다.

Step 수 5 (8.1 – 8.5)
누적 시간 ~100 분 (+ validation 실행 시간 상당)
선행 Phase Phase 6 (CI green), Phase 7 (수치 변경 목록)
종료 로그 009_phase08-statistical-revalidation.qmd

목표. tools/validation/ 의 검증 하네스가 현재 코드에서 동작하게 만든다.

작업.

  1. 하네스 구조 파악
    • tools/validation/validation-plan-manifest.csv — V0–V12 정의
    • tools/validation/jobs/ — 실행 정의
    • tools/validation/R/ — 지원 코드
    • tools/validation/generated/ — 2026-05 결과 (~180 파일)
    • tools/validation/reports/
  2. 하네스를 현재 코드로 실행해보고 깨지는 부분 확인 — Phase 4/5/7 의 변경으로 인터페이스가 바뀌었을 수 있다
  3. 수정
  4. 2026-05 결과를 보존 — artifacts/validation-2026-05/ 로 복사. 비교 기준
  5. Linux 실행 경로 확보 — Phase 4 Step 4.3 의 Docker 정의를 재사용
  6. MULTISITEDGP_RUN_VALIDATION 게이트 확인 — helper-skip-policy.R 에 정의되어 있으나 실제로 쓰이는지

산출물.

  • 수정된 validation 하네스
  • artifacts/validation-2026-05/ — 이전 결과 보존

  • Linux 실행 경로가 확보되어 있다

13.3 Step 8.2 — P0 validation 재실행 (V0–V5)

항목 값
모드 단일
소요 ~20 분 (+ 실행 대기)
의존 8.1

목표. 우선순위 P0 validation experiment 를 macOS 와 Linux 양쪽에서 재실행한다.

대상 (2026-05 이력 기준).

ID 내용 2026-05 상태
V0 hello-world aggregate calibration BR5 로 blocker 해소
V01 marginal reporting contract BR2 로 해소
V02 JEBS seed stability BR4 로 해소
V03 Walters shrinkage consistency BR3 로 해소
V04 A2 solver feasible region BR1 로 해소
V05 — Step 9.3 에서 실행

작업.

  1. 각 experiment 를 macOS · Linux 에서 실행
  2. 3 방향 비교 — ① 2026-05 결과 vs 현재 macOS, ② 현재 macOS vs 현재 Linux, ③ 2026-05 blocker 해소 결론이 여전히 성립하는가
  3. ①에서 차이가 나면 Phase 7 의 수치 변경 목록과 대조. 목록에 없는 변화면 회귀다 — 멈추고 조사
  4. ②에서 차이가 나면 Phase 4 의 재현성 계약이 예상대로 동작하는지 확인
  5. 결과를 tools/validation/generated/ 에 v0.2.0 접두사로 저장

산출물.

  • validation 결과 CSV (macOS + Linux)
  • evidence/phase08/validation-p0-comparison.md — 3 방향 비교표

완료 조건.

  • V0–V05 가 두 플랫폼에서 실행됐다
  • 3 방향 비교가 완료되어 있다
  • 설명되지 않는 차이가 없다

13.4 Step 8.3 — P1/P2 validation 재실행 (V06–V12)

항목 값
모드 단일
소요 ~20 분 (+ 실행 대기)
의존 8.2

목표. 나머지 validation experiment 를 재실행한다.

대상. V06 (Student-t heavy tail tolerance, BR7), V08 (repeated-run canonical hash), V09 (zero rank alignment, BR6), V11 (scenario_audit artifact gate, BR8), V12 (JEBS pattern evidence, BR9), 그 외 manifest 에 정의된 것.

작업.

  1. Step 8.2 와 동일 절차
  2. V08 은 특별 취급 — repeated-run canonical hash 검증이며 Phase 4 의 계약 변경에 직접 영향받는다. 새 계약에 맞게 experiment 정의 자체를 갱신해야 할 수 있다
  3. V12 (JEBS pattern evidence) 도 특별 취급 — 논문 재현 증거. Phase 4 Step 4.4 의 fixture 재생성과 정합해야 한다
  4. cross_os_matrix_status 필드 — 2026-05 에는 "not_run_in_local_phase9_job" 이었다. 이제 실제 값으로 채운다

산출물.

  • validation 결과 CSV
  • evidence/phase08/validation-p1-p2-comparison.md

완료 조건.

  • 나머지 experiment 가 두 플랫폼에서 실행됐다
  • V08 이 새 재현성 계약에 맞게 갱신되어 통과한다
  • cross_os_matrix_status 가 실제 값이다

13.5 Step 8.4 — JEBS 재현 증거 갱신

항목 값
모드 단일
소요 ~20 분
의존 8.2, 8.3

목표. Lee et al. (2025) JEBS 논문 재현 증거를 v0.2.0 기준으로 갱신한다.

작업.

  1. JEBS 관련 아티팩트 전수 확인
    • tools/jebs-golden-fixtures/ — 생성 스크립트 + manifest
    • preset_jebs_paper(), preset_jebs_strict() 의 파라미터
    • V02 (seed stability), V12 (pattern evidence)
    • vignette("m1-statistical-dgp") 의 JEBS 대조
  2. 논문 값 재현 확인 — package 가 논문 부록 값을 재현하는가? 이것이 이 package 의 과학적 신뢰성의 뿌리다
  3. NEWS 의 “Known limitations” 중 “Exact reproduction of JEBS Figure 4(b) is deferred until digitized targets become available” — 이 상태가 유지되는지, 아니면 이번에 진전이 있는지
  4. 재현 증거를 문서화 — 어떤 값이 어떤 정밀도로 재현되는지

산출물.

  • evidence/phase08/jebs-reproduction-evidence.md — 논문 값 × package 값 × 일치 여부
  • 갱신된 JEBS fixture manifest

완료 조건.

  • JEBS 부록 값 재현이 확인되어 있다
  • 재현되지 않는 항목이 있으면 사유가 기록되어 있다
  • Figure 4(b) 관련 한계 서술이 현재 상태를 반영한다

13.6 Step 8.5 — 검증 종합 리포트

항목 값
모드 단일
소요 ~20 분
의존 8.2 – 8.4

목표. validation 결과를 하나의 리포트로 종합하고, tools/traceability/validation-index.csv 를 갱신한다.

작업.

  1. 종합 리포트 작성 — experiment 별: 목적 | 2026-05 결과 | v0.2.0 macOS | v0.2.0 Linux | 판정
  2. cross-OS 매트릭스 결론 — 이번에 처음으로 실제 cross-OS 검증이 이뤄진다. 정책 문서(cross-os-reproducibility-policy.md)의 주장이 증거로 뒷받침되는지 확인하고, 안 되면 정책을 정정
  3. tools/traceability/validation-index.csv 갱신
  4. 미해결 blocker 확인 — 2026-05 의 BR1–BR9 가 전부 종결 상태인지. 새 blocker 가 생겼으면 원장에 등재하고 릴리스 영향 판정
  5. tools/validation/README.md 갱신 — 재실행 방법
  6. NEWS 초안에 검증 항목 추가

산출물.

  • 갱신된 validation-index.csv
  • evidence/phase08/validation-synthesis.md

  • 모든 experiment 가 종합 리포트에 있다
  • cross-OS 결론이 증거와 함께 기록되어 있다
  • BR1–BR9 상태가 확인되어 있다
  • 새 blocker 가 있으면 릴리스 영향이 판정되어 있다

13.8 Phase 로그

009_phase08-statistical-revalidation.qmd + .html.

§4 에 3 방향 비교표 (2026-05 / v0.2.0 macOS / v0.2.0 Linux) 를 experiment 별로 넣는다. 이 표가 “통계적 주장이 여전히 성립한다” 의 증거다.

이 로그는 IES 보고서와 논문 supplement 에서 인용될 수 있으므로, 다른 로그보다 자기 완결성을 높인다 — 외부 파일 참조에 의존하지 않고 핵심 수치를 로그 안에 넣는다.
