## D5 — Linux 검증 수단 (원장 D-019, P0)

### 문제

Linux 에서 무엇도 실행할 수 없습니다. Docker/podman/colima 가 설치되어 있지 않고, 원격 push 는 보류 상태입니다.

이 때문에 다음이 막혀 있습니다.

| 막힌 작업 | 어느 Phase |
|---|---|
| `R-CMD-check` 5 cell 실패 내용 확정 | 2 (partial 로 남음) · 6 |
| `test-coverage` 실패 원인 확정 (후보 2 개 중) | 2 (partial) · 6 |
| 드리프트의 **플랫폼 간** 실측 | 4 Step 4.1 |
| golden fixture Linux 베이스라인 생성 | 4 Step 4.3 · 4.4 |
| snapshot Linux 재생성 | 4 Step 4.5 |
| CI green 확인 | 6 전체 · 11 |

### 선택지

| | 방법 | 얻는 것 | 비용 |
|---|---|---|---|
| **A** | **원격 push 승인** | 5-cell 매트릭스가 즉시 돌고 아티팩트를 회수할 수 있다. Phase 4 와 6 이 동시에 풀린다 | 작업 과정이 공개 저장소에 노출됨 (이미 승인한 추적 범위 그대로) |
| B | Docker 설치 | 로컬 반복 실험 가능, push 불필요 | 설치 필요. **CI green 확인은 여전히 push 를 요구**하므로 Phase 6 은 못 푼다 |
| C | A + B 둘 다 | 반복 실험은 Docker, 최종 확인은 CI | 둘 다의 비용 |

### 권고: **A (원격 push 승인)**

Phase 6 의 성공 기준 G2 가 "CI 6 개 workflow green, 연속 3 회" 이므로 **push 는 어차피 필요합니다.** 지금 승인하면 Phase 4 와 6 이 함께 풀리고, Docker 설치라는 추가 작업도 없습니다.

노출 범위는 이미 승인하신 추적 범위(`tools/`·`log/` 포함)와 동일합니다. 현재 커밋 8 건이 로컬에만 있어 디스크 사고 시 복구 수단이 없다는 점도 push 를 지지합니다.

**결정란**

- [ ] **A — 원격 push 승인 (권고)**
- [ ] B — Docker 설치 후 진행
- [ ] C — 둘 다
- [ ] 보류 — Phase 4·6 을 미루고 Phase 5·7 만 진행

::: {.callout-note}
보류를 택하셔도 **Phase 5(테스트)와 Phase 7(결함 수정)은 진행할 수 있습니다.** 둘 다 Linux 가 필요 없습니다. 다만 Phase 6(CI)이 밀리므로 전체 일정이 길어집니다.
:::

## D1 — 재현성 계약 재설계

### 무엇을 알아냈나

`canonical_hash()` 가 플랫폼 간 불일치하는 이유가 확정됐습니다. **버그가 아니라 달성 불가능한 계약이었습니다.**

- 기본 engine A2 가 `nleqslv` 를 `ftol = 1e-12` 로 돌립니다 (`sim_multisite()` 1 회당 5 회 호출)
- 5 개 시작점이 **모두 수렴 조건을 만족하면서 서로 약 5,000 ULP 떨어진 점**에 안착합니다 (상대오차 ~1e-12, 정확히 `ftol` 수준)
- 반면 해시는 double 을 반올림하지 않아 **1 ULP** 차이에도 뒤집힙니다

**계약이 요구하는 정밀도가 계산이 제공하는 정밀도보다 3~4 자릿수 엄격합니다.** 어느 플랫폼에서 재생성해도 다른 플랫폼에서는 반드시 깨집니다. `design_hash` 가 일치하고 `canonical_hash` 만 불일치한 것도 이것으로 설명됩니다 — design 객체에는 solver 출력이 들어가지 않습니다.

### 선택지

| | 옵션 | 고치는 지점 | 계약 |
|---|---|---|---|
| O1 | Linux 재생성 | 아티팩트만 | 여전히 달성 불가 → **기각 권고** |
| O2 | 허용 오차 해시 (유효숫자 9) | 해시 계층 | 완화 |
| O3 | 이중 계약 | 해시 계층 (추가) | 분리 |
| **O4** | **solver 출력 양자화 (유효숫자 10)** | **원인 지점** | **유지 — 달성 가능해짐** |

**O1 을 기각하는 이유**가 중요합니다. Linux 에서 재생성하면 Linux CI 는 green 이 되지만 macOS·Windows 에서 깨집니다 — 지금과 정확히 대칭입니다. PI 님의 개발 머신이 macOS 이므로 로컬에서 영구히 검증 불가 상태가 됩니다. **현재 정책이 의도한 구도가 바로 이것이고, 그 결과가 3 개월 red 였습니다.**

### 권고: **Step 4.1 에서 O4 를 시간 제한 두고 조사, 실패 시 O2**

O4 는 engine A2 가 solver 해를 반환할 때 유효숫자 10 자리로 양자화합니다. 그러면 모든 플랫폼이 같은 `alpha`/`beta` 를 얻고, 이후 `rgamma` 등은 R 자체 코드라 플랫폼 불변이므로 **데이터 전체가 안정**해집니다. 비트 단위 해시 계약을 **그대로 유지한 채** 달성 가능해집니다.

- **장점** — "같은 설계 + 같은 시드 → 어디서나 같은 결과" 라는 약속을 지킵니다. 시뮬레이션 재현성 도구의 핵심 주장입니다
- **위험** — 수치 동작이 바뀌므로 fixture 전면 재생성 + JEBS 재현 재검증이 필요합니다. 그리고 A2 외에 다른 플랫폼 의존 연산(`sn` 내부 등)이 남아 있을 가능성을 배제하지 못했습니다
- **시간 제한** — Linux 대조 2 회 안에 드리프트가 사라지지 않으면 O2 로 전환합니다. 어느 쪽이든 fixture 는 한 번 재생성되므로 전환 비용이 작습니다

- [ ] O2 즉시 채택 (O4 조사 생략 — 더 빠르고 확실)
- [ ] O3 채택
- [ ] O1 채택

## D3 — 테스트 게이트 정책

### 무엇을 알아냈나

계획서는 slow 테스트의 표본 크기를 **줄여야** 기본 스위트에 넣을 수 있다고 전제했습니다. 실측이 그 전제를 뒤집었습니다.

| 실행 | 시간 | skip |
|---|--:|--:|
| 기본 | 18.1 초 | 30 |
| 확장 (게이트 전부 on) | 112.7 초 | 1 |
| **차이** | **+94.6 초** | −29 |

**게이트를 전부 켜는 데 95 초면 됩니다.** 축소 없이도 2 분 미만이며 권고 예산 3 분 안에 여유 있게 들어옵니다.

### 권고: 축소 없이 29 건 전부 제거

- `skip_if_not_slow` 17 + `skip_if_not_property` 12 = **29 건 제거**
- `skip_if_not_installed` 10 건은 **유지** (soft-dep guard, 정상 설계)
- 미사용 helper 2 개(`skip_if_not_validation`, `skip_if_api_missing`) 제거
- T1a 는 D1 에 종속 — **D1 이 O2 또는 O4 면 최종 skip 은 0 이 됩니다**

**부수 효과: Phase 5 가 8 Step → 6 Step 으로 줄어 약 40 분이 절약됩니다.** 절약분을 커버리지 보강에 재배분하는 것을 권고합니다.
