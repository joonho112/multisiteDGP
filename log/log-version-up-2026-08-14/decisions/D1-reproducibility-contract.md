- **작성:** 2026-08-14, Phase 3 Step 3.1
- **근거:** `evidence/phase02/reproducibility-contract-audit.md`, `evidence/phase02/hash-drift-analysis.txt`
- **막는 것:** Phase 4 전체
- **되돌릴 수 있나:** 부분 — 스키마 변경은 되돌릴 수 있으나 재생성된 fixture 는 이전 버전을 보존해야 복구 가능

---

## 1. 결정해야 하는 것

`canonical_hash()` 가 플랫폼 간 일치하지 않는다. Phase 2 가 원인을 확정했다.

| 사실 | 값 |
|---|---|
| 해시의 double 반올림 | **없음** (1 ULP → 해시 변경) |
| 기본 engine | `A2_modern` (`nleqslv` 5 회/호출) |
| solver 해의 결정도 | **~5,000 ULP** (상대오차 ~1e-12 = `ftol`) |
| 계약이 요구하는 정밀도 | **1 ULP** |

**계약이 요구하는 정밀도가 계산이 제공하는 정밀도보다 3~4 자릿수 엄격하다.** 이는 구현 결함이 아니라 계약 설계의 문제다.

---

## 2. 옵션

Phase 2 의 규명 결과 계획서에 없던 네 번째 옵션(O4)이 드러났다.

| | 옵션 | 어디를 고치나 | 기존 해시 | 계약 강도 |
|---|---|---|---|---|
| **O1** | 현행 유지 + Linux 재생성 | 아티팩트만 | 유지 | 변화 없음 (여전히 달성 불가) |
| **O2** | 허용 오차 기반 해시 | 해시 계층 | **전부 무효** | 완화 |
| **O3** | 이중 계약 (`canonical_hash` + 신규) | 해시 계층 (추가) | 유지 | 분리 |
| **O4** | solver 출력 양자화 | **원인 지점** | **전부 무효** | **유지 (달성 가능해짐)** |

### O1 — 현행 유지 + Linux 재생성 · **기각 권고**

golden fixture 와 snapshot 을 Linux 에서 재생성해 정책과 일치시킨다.

**기각 사유.** 문제를 해결하지 않고 **이전시킨다.** Linux CI 는 green 이 되지만 macOS·Windows 에서 깨진다 — 지금과 정확히 대칭인 상황이다. PI 의 개발 머신이 macOS 이므로 `test-golden.R` 과 T1a 가 로컬에서 영구히 실패하거나 영구히 skip 된다. 현재 정책이 의도한 구도가 바로 이것이고, 그 결과가 3 개월 red 였다.

### O2 — 허용 오차 기반 해시

해시 payload 를 만들기 전에 수치를 고정 유효자리로 정규화한다.

```r
# .canonicalize_for_hash() 의 atomic double 분기에 추가
signif(x, digits = 9L)
```

**자리수 근거.** solver 결정도가 상대오차 ~1e-12 이므로 그보다 성긴 1e-9(유효숫자 9 자리)로 정규화하면 **여유 3 자릿수**를 둔다. 실제 수치 회귀는 1e-9 보다 훨씬 크게 나타나므로 검출력을 잃지 않는다.

| 장점 | 단점 |
|---|---|
| 세 플랫폼에서 같은 해시 — 개발 루프가 근본적으로 개선된다 | 기존 해시 문자열이 전부 무효 (fixture·snapshot·vignette·문서) |
| 구현이 국소적 (`utils-reproducibility.R` 1 곳) | 자리수 선택이 다소 자의적 — 근거는 있으나 임의성이 남는다 |
| **수치 동작을 바꾸지 않는다** — 데이터는 그대로, 해시만 관대해진다 | 정책상 "major-version reproducibility decision" 해당 |
| Linux 없이도 로컬에서 구현·검증 가능 | 1e-9 ~ 1e-12 사이의 미세 회귀는 놓친다 |

### O3 — 이중 계약

`canonical_hash()` 를 same-machine 계약으로 남기고 cross-platform 용 해시를 별도 export 한다.

| 장점 | 단점 |
|---|---|
| 기존 해시 문자열이 유효 — fixture 재생성 불필요 | API 표면 증가 (신규 export + 문서) |
| 두 목적을 명시적으로 분리 | 사용자가 어느 해시를 써야 하는지 계속 혼동 |
| 되돌리기 쉬움 | `test-golden.R` 의 바이너리 비교 문제는 별도 해결 필요 |

### O4 — solver 출력 양자화 · **1 순위 조사 권고**

engine A2 가 `nleqslv` 해를 반환할 때 **엔진 내부에서** 고정 정밀도로 양자화한다.

```r
# .fit_trunc_gamma_start() 에서
alpha <- signif(exp(fit$x[[1L]]), 10L)
beta  <- signif(exp(fit$x[[2L]]), 10L)
```

solver 결정도(~1e-12)보다 성긴 1e-10 으로 양자화하면 **모든 플랫폼이 같은 `alpha`/`beta` 를 얻는다.** 이후 `rgamma` 등은 R 자체 RNG·C 코드이므로 플랫폼 불변이고, 따라서 **데이터 전체가 플랫폼 안정**해진다. 비트 단위 해시 계약을 **그대로 유지한 채** 달성 가능해진다.

| 장점 | 단점 |
|---|---|
| **계약을 지킨다** — "같은 design + 같은 seed → 어디서나 같은 해시" 라는 과학적으로 가치 있는 약속이 실제로 성립 | **수치 동작이 바뀐다** — fixture 전면 재생성 + JEBS 재현 재검증 필요 |
| 원인 지점을 고친다 (증상이 아니라) | 잔여 위험 — A2 외에 다른 플랫폼 의존 연산이 남아 있을 수 있다 (`sn::rsn` 등) |
| 해시 스키마 불변 | Linux 없이는 **검증할 수 없다** |

::: {.callout-warning title="O4 의 잔여 위험"}
Phase 2 는 `nleqslv` 가 R/ 전체에서 `layer2-engine-a2.R` 에만 있음을 확인했고 다른 layer 는 `uniroot`/`optimize`/`optim`/`integrate` 를 쓰지 않는다. 그러나 **`sn` package 내부의 `qsn`/`rsn` 이나 libm 초월함수 호출이 남아 있을 가능성**은 배제하지 못했다. Linux 대조 없이는 O4 가 드리프트를 **완전히** 없애는지 확인할 수 없다.
:::

## 3. 권고

**Step 4.1 에서 O4 를 시간 제한을 두고 조사하고, 완전히 닫히지 않으면 O2 로 전환한다.**

근거는 세 가지다.

1. **O4 는 사용자에게 가장 가치 있는 약속을 지킨다.** "같은 설계와 시드는 어디서나 같은 결과" 는 시뮬레이션 재현성 연구 도구의 핵심 주장이다. O2 는 그것을 "9 자리까지 같다" 로 완화한다 — 실용적으로는 충분하지만 약속이 약해진다.
2. **O4 와 O2 는 배타적이지 않다.** O4 를 적용해도 O2 를 나중에 얹을 수 있고, 그 반대도 된다. O4 를 먼저 시도하는 비용이 낮다.
3. **O1 은 기각, O3 는 차선.** O1 은 문제를 이전시킬 뿐이다. O3 는 안전하지만 표면이 늘고 `test-golden.R` 문제(D-007)를 따로 풀어야 한다.

**시간 제한 제안.** Step 4.1 에 O4 조사를 배정하되, Linux 대조 2 회 안에 드리프트가 완전히 사라지지 않으면 O2 로 전환한다. 어느 쪽이든 fixture 는 한 번 재생성되므로 전환 비용이 크지 않다.

### 두 옵션의 공통 작업

| 작업 | O4 | O2 |
|---|:--:|:--:|
| fixture 9 개 재생성 | ✓ | ✓ |
| snapshot 전면 재생성 | ✓ | ✓ |
| JEBS 재현 재검증 (Phase 8) | ✓ | — (데이터 불변) |
| 정책 문서 개정 | ✓ | ✓ |
| NEWS breaking change 명시 | ✓ | ✓ |
| **Linux 필요** | ✓ | 검증 단계에서만 |

## 4. D-007 (`test-golden.R`) 은 별도로 처리해야 한다

어느 옵션을 택하든 `test-golden.R` 이 `.rds` 9 개를 `compare_file_binary` 로 게이트 없이 비교하는 문제는 남는다. O4 가 성공하면 자연히 해소되지만, O2 를 택하면 **바이너리 비교는 여전히 깨진다** (해시는 관대해져도 RDS 바이트는 그대로다).

O2 채택 시 Phase 4 는 `test-golden.R` 을 다음 중 하나로 바꿔야 한다.

- fixture 를 읽어 `canonical_hash()` 로 비교 (바이너리 대신 계약 기반)
- 통계적 동등성 비교 (`all.equal` with tolerance)
- Linux 게이트 추가 (`skip_if_not_linux_strict_hash()`)

**첫 번째를 권고한다** — 계약과 검증 방식을 일치시킨다.
