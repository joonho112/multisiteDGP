## 1. 결정해야 하는 것

기본 `devtools::test()` 가 통계 불변량 30 건을 skip 한다. 성공 기준 **G3** 은 skip ≤ 3 을 요구한다. 어떻게 줄일 것인가.

계획서 Ch.9(Phase 5)는 slow 테스트의 **표본 크기·격자를 축소**해야 기본 스위트에 넣을 수 있다고 전제했다. Phase 1 의 실측이 그 전제를 뒤집었다.

## 4. 4 분류 배정

계획서 Ch.7 Step 3.3 의 4 분류를 적용한다.

| 분류 | 대상 | 건수 |
|---|---|--:|
| **① 그대로 켠다** | `skip_if_not_slow` 17 + `skip_if_not_property` 12 | **29** |
| ② 비용을 줄여서 켠다 | (없음) | 0 |
| ③ 분할한다 | (없음) | 0 |
| **④ 확장 스위트로 남긴다** | T1a (`skip_if_not_linux_strict_hash`) | **1** |

**①이 29 건 전부다.** 축소가 필요 없으므로 ②·③이 비어 있다.

### T1a 를 ④에 남기는 이유

T1a 는 D1 결정에 종속된다.

- **D1 = O4 (solver 양자화) 채택 시** — 드리프트가 사라지므로 게이트를 제거하고 세 플랫폼에서 실행한다. ①로 이동
- **D1 = O2 (허용 오차 해시) 채택 시** — 해시가 플랫폼 간 일치하므로 마찬가지로 게이트 제거. ①로 이동
- **D1 = O1 또는 O3 채택 시** — Linux 게이트 유지. ④에 남되 **CI 의 Linux cell 에서 실제로 실행되는지** Phase 6 이 확인

즉 **D1 이 O2 또는 O4 면 최종 skip 은 0 이 된다.**

## 5. 권고

**게이트 29 건을 축소 없이 전부 제거한다.**

1. `skip_if_not_slow()` 와 `skip_if_not_property()` 호출을 테스트 파일에서 제거한다
2. `helper-skip-policy.R` 에서 두 helper 와 미사용 helper 2 개(`skip_if_not_validation`, `skip_if_api_missing`)를 제거한다 — 원장 D-016 동시 해소
3. `skip_if_not_installed()` 10 건은 **유지한다** — soft-dep guard 는 정상적인 설계다
4. T1a 는 D1 결정에 따라 처리한다

### 시간 예산

| 항목 | 값 |
|---|---|
| 기본 스위트 목표 | **3 분 이내** |

| Phase 5 종료 시 재측정 | 필수 — 회귀 테스트 추가분이 더해진다 |

### 확장 스위트의 재정의

게이트가 사라지면 `extended-tests` workflow 가 기본 스위트와 같은 것을 돌리게 된다. **확장 스위트의 존재 이유를 다시 정의해야 한다.** 권고:

| 확장 스위트에 남길 것 | 이유 |
|---|---|
| validation smoke (V0) | 이미 별도 스텝으로 존재 |
| 전수 파라미터 격자 (필요 시 Phase 5 에서 신설) | 기본 스위트는 대표점만 |
| 장시간 property 탐색 (필요 시) | |

**Phase 5 Step 5.8 이 확장 스위트 정의를 확정하고, Phase 6 Step 6.5 가 workflow 에 반영한다.**
